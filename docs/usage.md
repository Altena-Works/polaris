## ビルドと一発実行

Rust `1.96.0` と `edition 2024` を使う。

```sh
cargo build --release
```

- リリースビルド前は `cargo run -p polaris-cli --` の後ろに同じ引数を続けられる。
- `exec [PROMPT]` は `--prompt` / `-p` と同じ one-shot 実行の別名であり、引数を省略するか `-` を渡すと標準入力から指示を読む。

### 基本の環境変数

| 変数 | 既定値 | 意味 |
| --- | --- | --- |
| `POLARIS_PROVIDER` | 自動選択 | API keyがあれば `openai`、なければ保存済みChatGPT認証・登録があるとき `codex`、いずれも無ければログイン画面へ進む。明示指定は `openai`・`codex`・`llamacpp`。 |
| `POLARIS_API_KEY` | なし | `POLARIS_PROVIDER=openai` で必要なOpenAI互換エンドポイントのAPIキー。 |
| `POLARIS_BASE_URL` | `https://api.openai.com/v1` | `openai` プロバイダのベースURL。 |
| `POLARIS_MODEL` | TUI: `gpt-6.1-sol`<br>単発: `gpt-6-astra` | 対話画面の推奨はSol。明示した `--model` が優先し、次にこの環境変数を使う。 |

### 推論強度（Effort）とプロバイダの仕様

- **推論強度の既定値と優先順**：one-shot 実行では省略時に `xhigh` を使う。対話TUIでは省略時に自動判定し、`--effort` で明示した値が優先される。APIにはモデル名と推論強度を別々に渡す。この設定は root 実行自身の強度であり、委譲先の強度は `[tier.*]` が決める。
- **指定可能な値**：CLIが受け付ける値は `low`・`medium`・`high`・`xhigh`・`max` の5つである。`max` は Responses API 限定だが、主経路が `/responses` なので使える。
- **モデルごとの強度範囲**：
  - `gpt-6-luna`・`gpt-6.1-terra`・`gpt-6.1-sol`：`medium` 〜 `max`（強さを指定しないとき、`gpt-6-luna` だけは `high` で動かす）
  - `gpt-6-astra`：`high` 〜 `max`
  - ※ これより低い指定は下限へ引き上げる。
- **`openai` プロバイダの制約**：現行の `openai` プロバイダは `/chat/completions` を使う。公式仕様では Astra の tool calling に Responses API が必要なため、この経路での Astra のツール実行は非対応である。`codex` プロバイダは別の Responses 形式の実装であり、APIキー用の Responses 対応とは区別する（[Astra移行ガイド](https://developers.openai.com/api/docs/guides/latest-model)）。
- **Web検索（`--web-search`）**：`disabled`、`cached`、`live` を受け付けるが、現在のChatGPT認証先は Responses 形式の上限契約を確認していない。既定の `disabled` だけが利用でき、`cached` と `live` は明示しても開始前に拒否される（`cached` もローカルのオフライン検索を意味しない）。動作する live 用コマンドはまだ案内しない。内部の Web 検索経路と上記の提供条件は維持している。

### 補助サブコマンド（sandbox / doctor / completion）

- `polaris sandbox -- <コマンド...>`：エージェントループを介さず、選択中のサンドボックスポリシーでコマンドを実行し、終了コードと標準出力・標準エラーを返す。
- `polaris doctor`：保存済み資格情報、既定プロバイダ、サンドボックスの可否を読み取り専用で診断し、鍵の中身は表示しない。
- `polaris completion <bash|zsh|fish|elvish|powershell>`：補完スクリプトを標準出力へ生成する。

## 記憶と環境変数の設定

### 1. `POLARIS_TURN_ONLY`（turn-only 記憶方式）

各ユーザーターンの要求に、そのターンと外部記憶だけを載せる設定です。
- **既定値**：有効（未設定で有効）。`off` または空の値で無効になり、従来どおり履歴を載せて自動圧縮します。
- **適用外**：履歴方式が `strict10`・`structured10` の会話には適用しません。

#### 記憶の4層構造
1. **原本**：終わったターンの各メッセージ（入力・ツールの結果・回答）を、後述する「ふるい」にかけてから400文字までのチャンクに切り、会話の中の位置を付けて約1MBまで持ちます（`POLARIS_TURN_ONLY_LOG_BYTES` で変更でき、古いものから落とします）。
2. **索引**：チャンクを語（BM25）で引き、ローカルの埋め込み（`multilingual-e5-small`）が使えるときは意味でも引いて、2つの順位を合わせます。
3. **台帳**：各ターン（入力とその返答）を圧縮した1行（`topic=..; asked=..; did=..; chose=a > b; !x(理由); open=..; pref=..`）にし、引用元のチャンク（`src=`）と出てきたファイル（`at=`）を添えます。
   - 直近10行は毎回載せます。
   - そこから押し出された行は、判定機が「この文脈に固有」と判定した語をその行とともに**辞書**へ入れ、行そのものも索引に加え、会話の方向を表す1行（**方向の行**）へ畳み込みます。判定機がないときは、パス・識別子・引用だけを残します。
   - 台帳の行と方向の行は最も軽いTier（`gpt-6-luna`）が書き、元のターンにないパスや識別子を含む行や長すぎる行は使わず、ターン自身の言葉から作った行で代えます。セッションのモデル（メインのLLM）はこの圧縮に使いません。
4. **確定事項**：台帳の行の `chose=` のうち、照合できる語（パス・識別子・引用・数値）を含み、それがすべてそのターンの原文にあるものに限ります。
   - そのうえで、「利用者の入力がその語をすべて含む（数字だけの一致は数えません）」か、「入力の全体が承認の一言（『これで進める』『ok』など）で、直前の回答がその語をすべて含む」ものだけを入れます。否定や条件の付いた入力は承認と見なしません。
   - この判定にモデルは使いません。思い出すたびに根拠のチャンクがまだ残っているかを確かめ、消えていれば根拠がないことを示します。

#### 要求への載せ方と会話サイクルの扱い
- **過去の引用の組み立て**：次のターンの要求には前のターンの原文を載せず、「確定事項・方向の行・直近10行・入力が名指しした辞書の語・入力に近いチャンク」を、合わせて **2,048トークン** までの過去の引用として1通だけ載せます。
- **チャンクの件数上限（8件）**：入力に近いチャンクは引用の最後に、近い順に8件まで、枠の残りに収まる分だけ載せます。入力が直近の質問と言い回しを共有していると、その質問自身のチャンクが先に来て、遠い資料の値を含むチャンクが5番目前後まで下がることがあります。枠に余裕があるのに件数で切るとその値が引用に載らないことがあるため、8件にしています。
- **自動圧縮の不実施**：保存される会話は変えず、要求だけが前のターンを外します。要求に前のターンを載せないため履歴の自動圧縮は行いません。このため、1回のターンが長く続いて要求が文脈の長さを超えても圧縮では防げず、providerのエラーとして現れます（保存した会話と記憶は失われません）。
- **記憶の寿命と会話の切り替え**：
  - 記憶は会話と一緒には保存しないため、`-p` で起動し直すたびに作り直し、台帳の行もそのつど書き直します。
  - 記憶は1つの会話に属します。`/clear` はその記憶も捨て、これ以後の会話を新しい記憶に取り込みます。
  - `/new`・`/resume`・`/new fork`・巻き戻し・sidechatで別の会話に移ったときは、移った先の会話から記憶を作ります。
  - 台帳の行を書くモデルと埋め込みは起動時に1度だけ選び、どの会話の記憶にも同じものを使うため、会話を移っても失いません。
  - `[decision]` に `local_only = true` があるときは、行を書くモデルに通信制限を確認できるものだけを使い、確認できないときはモデルを呼ばずにターン自身の言葉から行を作ります。

#### 取り込みの2段階プロセスと中断時の扱い
取り込んだ位置は、メッセージの位置でなくターンの番号で持ちます。

1. **第1段（要求を送る反復ごと）**：ツールの結果を履歴で縮める処理（`--tool-memory` を指定したとき）があれば、その直前に行います。まだ取り込んでいない新しいメッセージを、ふるいにかけた全文のまま「保留」に入れます。履歴で縮められる前の全文が原本に入るため、長いツールの結果も縮められずにチャンクになります。
2. **第2段（ターンが完了したとき）**：保留を原本のチャンクに確定し、台帳の行と確定事項を作ります。この段は、結果をすべて作り終えてから状態を一度に更新します。行を書いている途中で中断しても、チャンクの一部だけが残ることも、同じターンが二重に数えられることも、台帳から押し出す行が失われることもありません。
   - 完了の処理は実行の中で行うため、台帳の行を書くモデルへの要求は回答を表示する前に済みます。完了の処理の途中で `Esc` を押したときも実行ごと止まり、すでにできあがった回答まで履歴から巻き戻され、記憶にも入りません。
- **未完了・中断時の処理**：
  - ターンが完了しないまま終わったときは、保留を捨て、台帳には何も入れません（エラー終了時は実行を包む処理が捨て、TUIの `Esc` 中断や終了信号では履歴を巻き戻す処理が捨てます）。
  - 次に実行を始めるときも、保留は必ず捨てます。そのうえで、履歴に残っていて完了の処理をしていない終わったターン（入力だけが残ったターンや、保存した会話から読み戻したターンなど）を、履歴にあるとおりに取り込んで完了させます。このとき履歴のツールの結果がすでに縮められていれば、記憶に入るのは縮められた後の文字列です。
  - デスクトップのサービス（`polaris-desktop-service`）は、実行の終わりに完了の処理をしません。最後のターンは、次の実行の始めに履歴から取り込んで完了させます。

#### 秘密情報のふるい分け（`screen_for_memory`）と経路保護
記憶に入る文字列は、記憶専用のふるい `screen_for_memory` を通します（監査ログ・MCP・回答の最終確認が使う `screen_text` とは別の規則で、`screen_text` は変えていません）。

**ふるいが伏せる対象：**
- **接頭辞で分かるトークン**：`sk-`・`ghp_`・`github_pat_`・`xox`・`AKIA` など。続く文字の種類は問いません。
- **YAMLとJSONの秘密キーの値**：秘密を表す名前（`password`・`secret`・`token`・`api_key` など）のキーの値。
  - 引用符のない値に語が続くとき（`password: correct horse battery staple`）は、コードでなければ行末までを値と見なします。
  - 値が参照のとき（`${DB_PASSWORD}`・`<your token>`・`{{ vault.secret }}`・`!secret db_password` など）は伏せません。参照と見なすのは、値の全体がその形のときだけです。`!`・`@`・`*` で始まるだけの値（`password: !Passw0rd`）は伏せます。参照の後ろの `,`・`;`・`)`・`]` は、値の終わりにあるときだけ参照の一部と見なします（`TOKEN=$X,hunter2value` は伏せ、`TOKEN=$X;` は伏せません）。
  - キーと値の組と代入では、引用符のない `&` か `*` だけの値で、後ろに語が続かないもの（Rustの `token: &'a str,` の `&`、伏せ字の `********`）は秘密と見なしません。記号だけの値でも、引用符つき（`password: "!@#$%^&*"`）や、それ以外の記号を含むものは伏せます。
- **環境変数・設定・オプション**：秘密を表す名前の環境変数への代入（`GITHUB_TOKEN=...`）、引用符のついた設定（`api_key = "..."`）、同じ名前の長いオプション（`--password ...`）。
  - 個数を表す `max_tokens=256` は伏せません。キーと値の組は、秘密を表す名前のものだけを対象にします。秘密を表す名前でない組が前にあっても（`INFO: password: ...`、`?limit=10&api_key=...`）、後ろの秘密を表す名前の組は伏せます。
- **認証ヘッダー・鍵**：`Authorization` ヘッダー、`Bearer` トークン、URLの中のパスワード、PEM形式の秘密鍵。
- **長いランダムな文字列**：24字以上で、数字と英字を含み、文字のばらつきが大きいものに限ります。
  - 大文字と小文字が混ざって語でできているもの（`RewindBoundaryCompletionV1`）や、gitのハッシュ（40字・64字の16進）は伏せません。
  - `_`・`/`・`-` を含むものは、その間の部分で判断します。部分が語・数字・ハッシュ（7桁以上の16進）でできているもの（識別子・パス・UUID・版番号・コミットのハッシュを含むパス。`Sources/PolarisSettings/BootstrapV2Publisher` など）は伏せません。
  - 語・数字・ハッシュのどれでもない部分が合わせて16字以上あり、大文字・小文字・数字をすべて含むもの（`wJalrXUtnFEMI/K7MDENG/...` のようなbase64やbase64urlの鍵）は伏せます。
  - ※「語」とは、大文字1字に小文字2字以上、小文字3字以上、大文字2字以上の並びです。数字には、前と後ろに大文字を1字ずつ付けられます（`V2`・`2D`）。

> [!NOTE]
> **誤検知率とテスト**：このリポジトリの `crates/**/*.rs` にある20字以上の識別子のうち、ふるいが伏せるのは1%以下です。測った値は0.15%ほどで（`screen_text` は27%ほど）、上限の1%は `crates/polaris-core/tests/memory_screen.rs` が毎回測ります。

**検査のタイミングと拒否パスの扱い：**
- **チャンク化前の検査**：ふるいにかけるのは、メッセージを1通ずつ、チャンクに切る前の全体に1回です。判定（そのまま・伏せた・捨てた）はそのメッセージのチャンクに記録し、以後は伏せた後の文字列だけを使います（埋め込みも伏せた後の文字列から作ります）。全体が秘密だけのメッセージは本文を残さず、番号を進めて `withheld` の1行にします。その行を根拠にする確定事項は「未支持」と示します。記憶の外へ出る文字列と引用に載る文字列は、すべて1つの関門を通ります。関門は秘密を伏せるだけで、書き手に送ってよいかどうかは取り込み時に記録した判定で決めます。
- **拒否されたパスの除外**：拒否されたパスを読んだツールの結果は、本文を記憶に入れません。`read`・`write`・`edit` は引数 `path` を、`bash` は引数 `command` を、空白・引用符・リダイレクト記号などで語に分け、先頭の `~` と `$HOME` を展開して、語ごとに読み取りを拒否するパスかどうかを調べます（`.env` のような裸の名前も調べます）。結果の行頭が拒否される名前のとき（`grep -r` が出す `path:行` など）も同じ扱いです。当たった結果は、本文を持たない `withheld: denied path` の1行になります。台帳の `at=` と辞書のパス候補にも同じ判定をかけ、1件を200字までにします。
- **ツール出力の印**：記憶の引用では、ツールの出力に由来するチャンクに1件ずつ `untrusted tool output (turn N)` の印を付けます。ツールの出力は指示ではなく、読み取った資料として扱うためです。

**各モデル・機構へ送るデータと上限：**
台帳の行を書くモデルが受け取るのは、そのターンの入力と回答の先頭だけです。入力か回答のどちらかをふるいが伏せた（または捨てた）ターンでは、モデルを呼ばず、ターン自身の言葉から行を作ります。ツールの結果はモデルに送らず、この判定にも使いません。

| 送る先 | 送るもの | 条件と上限 |
| --- | --- | --- |
| **台帳の行を書くモデル**<br>（最も軽いTier） | そのターンの入力と回答の先頭<br>（`USER: ...` と `ASSISTANT: ...`） | 入力と回答がふるいを通ってそのままだったターンだけ。先頭3文・600字ずつで、全体1,500字まで。`local_only = true` のときは通信制限を確認できるモデルだけ。ツールの結果は送らない。 |
| **同じモデル**<br>（畳み込み） | 方向の行と、直近10行から押し出された台帳の行 | 関門を通した文字列だけ。押し出された行には、ふるいが伏せた後の文字列が含まれることがある。`local_only = true` の条件は同じ。 |
| **判定機**<br>（`[decision]`） | 押し出された台帳の行の先頭1,500字と、辞書に入れる候補の語ごとの問い | 候補はパス・識別子・引用・名前のうち、秘密らしい形でなく、ふるいにも当たらず、拒否されるパスでないもの。送る前に関門を通す。`local_only = true` のときは通信制限を確認できる判定機だけ。 |
| **ローカルの埋め込み** | チャンクと、入力の問い合わせ<br>（どちらも伏せた後の文字列） | 捨てた行（`withheld`）は埋め込まない。 |
| **メインのモデル** | 今のターンのメッセージと、過去の引用1通 | 引用の各行は関門を通す。ツール由来のチャンクには印を付ける。 |

> [!WARNING]
> **ふるいで防げないもの（限界）**
> - `bash` がファイルを名指しせずに読む形（glob・`find -exec`・`tar` など）は、コマンドの語から拒否されるパスを見つけられません。結果の行頭にも拒否される名前が出なければ止められません。
> - ふるいが伏せるのは、上に挙げた形に当たったものだけです。TOMLやINIの引用符のない `name = value` は伏せません。
> - `_`・`/`・`-` を含む長いランダムな文字列のうち、大文字・小文字・数字のどれかを欠くもの（小文字の16進を `-` でつないだ形など）と、語・数字・ハッシュのどれでもない部分が16字に満たないものは、前後に手がかりがなければ伏せません。ふるいは秘密を完全に防ぐものではありません。

### 2. その他の実験設定（Quality / Effort / Economy / Pacing）

#### `POLARIS_QUALITY`（終了時の確認と差し戻し）
ルートの終了時の確認を有効にする実験設定です。既定は無効で、カンマ区切りで次の名前を指定します。サブエージェントには適用しません。
- `completion`：このターンで `write`・`edit` をした後、要件を実行で確かめ直すよう1回だけ差し戻します。直近の編集後のコマンドが失敗していれば、それを先に解決するよう促します。
- `loop`：同じツールエラーが3回続いたとき、停止する前に別の方法を試すよう1回だけ促します。
- `blocker`：最終回答に実行不能や制約違反を示す語があれば、自分で置いた仮定を制約内で見直し、矛盾して見える要求がそれぞれ何に適用されるかを確かめるよう差し戻します。語による判定のため、実行不能を宣言していない説明にも反応する場合があります。
- `data`：編集後、プロジェクト内のJSONにある小文字の識別子キーのうち、走査対象のコードに名前が現れないものを列挙し、使用する必要があるか確認を促します（名前があることだけで正しい使用を保証するものではありません）。`blocker` と同時に働く場合は1通にまとめ、合わせて1回だけ差し戻します。
- `lean`：`unattended` プロファイルに、課題から求められていなければ試験ファイルを追加せず、一時的なコマンドやスクリプトで確認する指示を加えます。
- ※ 差戻しの判定自体はモデルを呼びませんが、差戻し後の応答には追加のモデル要求と費用が発生します。各設定の効果は実測して判断します。

#### `POLARIS_EFFORT_PLAN`（要求ごとの推論強度の動的変更）
ルートの1回の実行の中で、要求ごとに推論の強さを変える実験設定です。既定は無効で、下げた先の強さ（`medium`・`high`・`xhigh`）を指定します。
- 下げるのは、**最初に変更する前に `read` が2回続いた後の要求だけ**です。コマンド（`bash`）の結果を読む要求は、解釈や判断を伴うことが多いため下げません。
- 最初の変更（`write`・`edit`、またはファイルへ書き込むコマンド）より後は、そのターンの強さで固定します。強さを切り替えるたびにサーバー側のキャッシュが外れるため、切替えの回数を抑えています。
- モデルは変えず、同じモデルの強さだけを変えます。セッションの強さより上げることはなく、強さが未設定（アカウントの既定）のときは何も変えません。実行が終わるとそのターンの強さに戻します。判定は履歴だけで行い、モデルを呼びません。

#### `POLARIS_TOOL_ECONOMY`（ツールの往復削減）
工具の往復を減らす実験設定です。既定は無効で、使う項目をカンマ区切りで指定します。
- `edit`：`edit` の結果に、変更した行と前後3行を行番号付きで添えます。変更を確かめるための読み直しが要らなくなります。
- `dir`：ディレクトリを `read` したとき（`offset` が0のとき）、一覧に続けて、直下の小さなファイルの中身を合計32KBまで添えます。入りきらないファイルは数だけを示し、個別の `read` に任せます。
- ※ どちらも `read` が拒否するパスは読みません。隔離した読み取りの環境では働きません。

#### `POLARIS_SPAWN_EFFORT`（下位エージェントの推論強度の自動判定）
下位エージェントの推論の強さを、判定機が判定した難易度で決める実験設定です。既定は無効で、`off`・空以外の値で有効になります（推奨は `on`）。
- 判定機（`[decision]`）が委譲の難易度に答えたときだけ働き、軽い仕事（`dwarf`）は `medium`、通常（`subgiant`）は `high`、重い仕事（`giant`・`supergiant`）は `xhigh` で子を動かします。
- 判定は委譲の束ごとに1回で、1つの子の中では強さを変えません。セッションや `[tier.*]` の強さより上げることはありません。
- 続きを引き継ぐ型（`implementer`）は、最初に決まったTierと強さのまま続け、途中でモデルを変えません。判定機が答えなかったときは、今までどおりの強さです。

#### `POLARIS_CACHE_PACING`（要求間隔の制御）
既定は `off`。`on` は同じ Codex provider のモデル要求開始を最低5秒間隔にする実験設定で、完了までの時間が伸びる場合がある（[比較条件と結果](gpt6-cache-pacing-results.md)を参照）。

## 起動時のトラブル

### ホームディレクトリからの起動拒否
`polaris` は作業対象のプロジェクトディレクトリから起動する。

```sh
cd /path/to/project
polaris
```

ホームディレクトリで起動すると、既定の書込み範囲に実行用バイナリと保護用の保存先が入り、`Isolated execution preparation refused: RuntimeDenied` で停止する場合がある。プロジェクトへ移動して再起動する。ホームからの起動を自動調整する修正は未実装であり、サンドボックスを解除して回避しない。

### 認証時のブラウザ起動とURL操作
- 認証待ちでブラウザが表示されなければ、`Enter` または `o` で再度開くか、`c` でクエリ付きURL全文をコピーして通常のブラウザで開く。認可が終わるまで polaris の画面は閉じない。
- Terminal.app の `Cmd + 単クリック` は polaris へ通知されず、現在の実装では開けない。`Ctrl-click` または上記のキー操作を使う。

### macOS 端末でのマウス・D&D操作
- **ファイル・URLのクリック**：macOSでは会話に表示された実在ファイル名を `Ctrl-click` すると、Finderで所在を表示する。認証URLも `Ctrl-click` で開ける。`Cmd-click` は端末が修飾キーを通知する場合に対応する（Terminal.app 標準のURL操作は `Cmd-double-click` である）。通常のクリックでは開かない。
- **ドラッグ選択によるコピー**：ログイン画面・ダイアログ・実行中も、表示された文字をドラッグして離すと確認なしでコピーする。非表示の秘密値はコピーしない。
- **ファイルのD&D**：ファイルを端末へドラッグ＆ドロップすると、入力欄にファイル名のリンクブロックを挿入し、直後の `Backspace` で一括削除できる。ファイル本文は自動で読み込まない。

## 固定profileによる環境構築

macOS arm64では、例えば空の対象 directory で次を実行する。

```sh
polaris env set nextjs --path /absolute/path/to/project
```

- **動作と特徴**：対象・対応版・固定資源・作成先を1回確認し、専用 runtime と cache を使って offline 導入・build/smoke・記録まで進む。対応 profile は `polaris env status` で確認する。モデルへの問い合わせは行わず、認証がない状態でもCLIから使える（TUIの `/env` は削除した）。
- **既存環境の保護**：既存 manifest/lock/source と既存の導入先は保持する。安全に対応できない依存や版は理由を表示して停止し、online mode や別 package manager へ暗黙に切り替えない。global な Node/Python/Rust/Go や shell 設定は変更しない。版や runtime の参照先は完了時の receipt を参照する。
- **Rust の Apple Toolchain 指定**：Rust で既存の Command Line Tools を明示選択する場合は、`POLARIS_ENVKIT_APPLE_TOOLCHAIN=command-line-tools polaris env set rust` を使う（`plan` を別に作る場合も同じ変数を指定する）。未指定時は現在の Apple developer 選択を使い、Xcode の失敗から自動で切り替えない。global 設定やライセンス同意状態は変更しない。
- **計画の保存と復旧**：`polaris env plan` は取得前の計画を保存する。停止時は表示された retained root を保持し、`polaris env status --operation <retained-root>` で確認する。復旧は保存物の照合を行い、通信・script・publish を繰り返さない（[全構文と提供範囲](command-reference.md#環境構築)を参照）。
- **自然文からの環境構築**：任意の `builtin:envkit` skill と root 専用の typed `environment` tool を用意している。skill を読むこと自体は実行権限を与えず、host による計画承認が必要である。旧 `polaris setting nextjs` は提供しない（`setting git` は Git 補助として保持する）。

## workflowと厳密履歴

設定は `~/.polaris/config.toml` と `<project-root>/.polaris/config.toml` に置く。プロジェクトで明示した値が優先し、未指定の値はグローバル設定を継承する。

### workflow の設定と再開
workflow は v0.11.0 から既定で有効である。常時 skill と段階別 skill を明示的に解決して各ターンへ固定し、通常の skill 検索ランキングとは混ぜない。段階は `general`、`brainstorm`、`specify`、`implement`、`review`、`verify`、`deliver` である。

```toml
[workflow]
enabled = true
initial_phase = "specify"
always = ["user:team-rules"]

[workflow.phase_skills]
implement = ["builtin:implement"]
review = ["user:review-rules"]
```

- 比較などで無効にする場合は `[workflow] enabled = false` を明示する。`--phase <段階>` は workflow が有効な起動だけで使える。
- `--resume <v2 UUID>` は保存済み v2 会話を続け、`--fork <v2 UUID>` は指定会話から新しい UUID を作る（両方は同時に指定できない）。旧 JSONL の ID を `--resume` へ渡した場合は、新しい v2 UUID へ一度だけ取り込む。
- 保存済みの会話は保存した workflow の設定で再開し、起動時の `[workflow]` 設定では変わらない。実行方式を変えるには、再開時に `--workflow-mode manual|adaptive|off` を指定し、確認画面で承認する。

### 履歴方式と自動圧縮
- 履歴方式の既定は `legacy` である。`--history-mode strict10` は直近10個の実ユーザーターンを保持し、固定したローカル埋め込み設定を必要とする。設定方法と保存境界は[コンテキスト効率化](context-efficiency.md)を参照。
- `legacy` の履歴は、要求の入力トークン数（providerが直前の要求で報告した数に、その後に足した分の推定を加えたもの。報告がないときは推定）がモデルの文脈の長さの **70%** に達すると自動で圧縮する。長さが分からないモデルでは、`200,000` に達したときに圧縮する。
- 手元のモデル（Ollama・LM Studio・llama.cpp）では、`config.toml` の先頭（最初の `[...]` 見出しより前）に `context_window = 8192` のようにトークン数を書くと、その値の70%に達したときに圧縮する。`openai` プロバイダでも、`POLARIS_BASE_URL` がループバックのアドレス（`127.0.0.1`・`::1`・`localhost`）を指すとき（手元の `llama-server` など）は同じ設定が効く。この設定はクラウドのモデルには効かない（決め方は[コンテキスト効率化](context-efficiency.md#圧縮と履歴保存)を参照）。

## 監査ログと記憶

- **監査ログ（`--audit <path>`）**：監査ログの出力先を指定できる。省略時は `~/.polaris/state/<project-id>/audit.jsonl` へ追記する。`<project-id>` は canonicalize 済みの作業ディレクトリから求め、リポジトリの外に置く。各ツール呼び出しを1行のJSONとして記録し、書き込み前に秘密情報を伏字化する。
- **ツール結果の記憶（`--tool-memory`）**：既定は `off` である。
  - `history`：直近2組の完了済みツール往復を保持し、それ以前の 8KiB 以上の `read`・`bash` 結果を保存して短い参照へ置き換える。
  - `retrieval`：大きな完了結果を初回送信前から参照と小抜粋へ置き換える。
  - 保存失敗時は全文を維持する。圧縮前履歴を保存する `--remember` とは独立している。保存、検索URI、埋め込み、ベンチマーク手順は[コンテキスト効率化](context-efficiency.md)にある。

## 型付き判断器の設定

`[decision]` は通常の会話モデルとは別の判断器を選ぶ設定で、既定は無効である。既存の Jev と SemIf は引き続き選択できる。モデルや helper が見つかっただけでは有効にならない。

| `backend` | 指定する資源 | 現在の扱い |
| --- | --- | --- |
| `jev` | 任意の `model`・`base_url` と、環境変数 `POLARIS_JEV_API_KEY` | 既存のHTTP経路。明示的に有効にした場合だけ使用する。 |
| `system-one` | 利用者 config の `[decision.system_one]` | 明示した System One HTTP 互換契約。接続先・モデル・認証参照をまとめて登録する。 |
| `semif` | `helper` への絶対 path | 既存のローカル helper 経路。Clef の導入状態にかかわらず維持する。 |
| `clef` | `model` に package 登録済みの固定 profile ID | macOS の管理対象 generation を使う。`helper`・`base_url` や任意の実行ファイル path は指定できない。 |

### 現在の提供状況・GUI操作・容量判定の仕様
- **Clef の受入状況**：Clef/Clef-flash はモデル、量子化、runtime、device、割当 context ごとに受入記録を持つ。**現在の本番 lock には受入済み profile がないため、Clef はまだ通常実行に使えない。** IDを設定するだけで受入済みにはならず、起動時に weights を自動取得することもない。未導入・未検証の Clef を選んだ場合は理由を表示し、Jev へ勝手に変更しない。Clef の answer finalizer も未対応である。
- **macOS Desktop / インストーラでの選択**：
  - macOS desktop の Jev スイッチは、選択中の backend が `jev` の場合だけ有効・無効を上書きする。`clef`・`semif`・`system-one` を選んでいる場合は、`[decision]` の `enabled` を維持する（Jev スイッチで他 backend を有効・無効にすることはない）。
  - インストーラの Clef 欄では、登録 profile を「無効のまま選択」できる。「再検証して有効化を選択」は、同梱CLIで導入済み generation の全SHAをその都度照合してから、選択を設定の下書きへ反映する。導入や検証だけでは有効にならない。設定を確定し、owner を終了して起動し直すと反映され、実行中の owner は切り替わらない。このGUI選択は desktop だけに適用され、CLI/TUIの設定は変更しない。
  - GUIで Clef を選んでいる間は fallback と Jev キーを使用せず、`local_only` などの制限と実行時の受入・整合性・容量検査を維持する。元の設定ファイル・Jev の選択・導入資源は変更しない。「この profile を無効にする」で型付き判断器を無効にでき、「設定ファイルと Jev スイッチの選択へ戻す」で元の設定を再適用できる（どちらも設定確定後の次回 owner 起動から反映する。登録 profile がなくなった場合もこの操作は使える）。
- **容量判定とメモリ予算**：
  - `polaris doctor` の容量帯と候補順は推薦の目安で、実行可能という判定ではない。8GB程度・16GB程度・24GB以上という容量帯で利用できる backend を固定しない。Clef/Clef-flash、SemIf、Jev は、利用者の選択と各 backend の実行条件に従って使用する。
  - 管理対象 CPU worker の起動直前には、空いている物理メモリから保守的な予算を求め、profile の peak と予備量を確認する。CPUの使用量をGPUへ換算せず、Metal の device 別容量観測が未対応の間は、その profile を実行しない。
  - desktop の入力分類・goal 確認には、構築済み主接続・要約・selector の資源契約を渡す。通常 run では準備済み provider 群を別に使い、早期判断の情報で上書きしない。embedding 等の実行時 peak が分からない場合は、file 容量や接続先がローカルであることから `0` を推定しない。
  - Clef の容量判定には、主会話・補助 selector・委譲先が今後追加するローカルモデル割当の計画を、呼出ごとに渡す。同一 provider instance は一度だけ数え、未確認値や加算 overflow を `0` と扱わない。既知の公式 cloud origin の client は追加のローカル weights を読み込まない契約として `0` を返すが、接続や認証の成功を意味しない。custom/loopback endpoint と未実測のローカルモデルは未確認のままとする。
  - 実行 owner は、同居予定量を既存の予備量へ加え、要求に紐付いた容量判定・budget・必要量・拒否理由を status/audit へ返す。判定はメモリ予約ではない。warm 時も検証済みの全 peak を保守的な上限として使い、未検証の常駐 RSS を差し引かない。strict 履歴の embedding など、まだ容量を束縛できない追加資源が有効な場合や、desktop で実行 provider 群が未確定の呼出では、Clef は同居容量未確認として拒否する（Jev/SemIf の選択経路は維持する）。
- **端末内限定設定（`local_only = true`）**：
  - 判断と補助モデルによる候補選択を端末内に限定したい場合は、`[decision]` に `local_only = true` を指定する（既定は `false`）。`true` の場合は通信制限を確認できる判断器と補助モデルだけを許可し、判断失敗後も外部の補助モデルへ送信しない。
  - loopback の接続先やローカル helper というだけでは、外部通信しない保証にはならない。現在の Jev HTTP 経路と、通信を制限していない SemIf helper は、この指定時には使用できない。管理対象 Clef も、受入・導入・容量の条件を別途満たす必要がある。
  - 利用者設定の `local_only = true` は、project 設定の `false` では解除できない。この設定が制限するのは判断と補助的な候補選択であり、通常の会話モデルやMCPツール自体の通信許可は別に設定する。

### System One互換接続

`system-one` は、`systemone-http-v1` の型付き要求・応答に対応する接続先を明示する設定である。通常の chat API や、モデル名が似ているサービスの互換性を保証するものではない。次は利用者の `~/.polaris/config.toml` に置く設定例で、接続先とモデルは実際のサービスの値に置き換える。

```toml
[decision]
enabled = true
backend = "system-one"

[decision.system_one]
endpoint = "https://example.invalid/systemone"
model = "REGISTERED_MODEL"
credential_env = "POLARIS_SYSTEM_ONE_KEY"
```

- **エンドポイントと認証変数**：`endpoint` は POST 先の完全なURLで、`base_url` や外側の `model`・`helper` とは併用しない。認証値は config へ書かず、`credential_env` で指定した環境変数を polaris の起動環境へ用意する。変数名は `POLARIS_SYSTEM_ONE_` で始まり、続く部分を含めて大文字英数字と `_` の128文字以内とする。この設定全体は利用者 config だけから読み、project config から接続先・モデル・認証参照を書き換えることはできない。無効時、`local_only = true`、未到達の fallback 先では認証値を参照しない。
- **通信条件と上限**：HTTPS を既定とし、HTTP は `allow_loopback_http = true` と literal loopback IP を両方指定した場合だけ許可する。URL の userinfo・query・fragment、redirect、通信層の自動再試行は拒否する。要求・応答は各 1MiB、質問・選択肢は各256件、通信の上限は30秒である（これは通信層の上限であり、モデルの context や容量を測定した値ではない）。接続先には state と質問が送られる。診断・監査に記録するURLは origin（scheme・host・port）までで、path と認証値は含めない。
- **検証と制約**：応答のモデル名と型付き回答を検証するが、実 weights の revision・量子化を証明するものではない。現在は未校正として候補を維持し、answer finalizer には使わない。loopback HTTP も通信の隔離を保証しないため、`local_only = true` では拒否する。明示 fallback の候補にする場合は、該当する `[[decision.fallback.targets]]` に `backend = "system-one"` を置き、その直後の `[decision.fallback.targets.system_one]` へ同じ設定項目を指定する。

### 型付きbackendの切替（Fallback）と監査・診断

型付き backend 間の切替は、利用者の `~/.polaris/config.toml` に明示した場合だけ行う。project 設定から切替先を追加することはできない。次は登録済み Clef profile を主に使い、未導入・利用不能などの場合に Jev へ切り替える設定例である（`REGISTERED_PROFILE_ID` は実際の登録IDへ置き換える。本番の受入済み Clef profile が0件である点はこの設定でも変わらない）。

```toml
[decision]
enabled = true
backend = "clef"
model = "REGISTERED_PROFILE_ID"

[decision.fallback]
purposes = ["routing"]
max_attempts = 2
attempt_timeout_ms = 60000
total_timeout_ms = 120000

[[decision.fallback.targets]]
backend = "jev"
model = "jev-latest"
base_url = "https://api.typesafe.ai/v1"
```

- **試行回数とタイムアウト**：`targets` は1〜3件を順番に指定する。`max_attempts` は主 backend を含めた試行数で、1から候補総数まで。各試行と全体の時間上限を必須とし、合計は最大 `300000ms` である。切替設定時の Jev は、backend 内で追加の再試行を行わない。起動時に候補の接続先・モデル・用途・上限を表示する。各接続先には state と質問を送り、依頼・会話やファイル由来の内容・候補の説明等が含まれる場合がある。
- **切替条件**：用途は `routing`（候補選択・委任先・継続判定等の通常の型付き判断）だけに対応し、単発の answer finalizer には適用しない。利用不能・入力超過・時間切れは次候補へ進めるが、認証失敗・設定不正・不正回答・取消では進めない。`local_only = true` と併用する場合は全候補で通信制限を確認できる必要があり、現在の Jev/SemIf を含む切替設定では型付き判断器を有効にしない。fallback 設定がなければ、他の型付き backend へ自動で切り替えない。
- **校正の扱い**：切替先へ主 backend の校正を流用しない。未校正モデルによる候補絞込みは候補を維持し、判断の呼出自体を省く場合がある。既存の生成モデルによる候補選択は、型付き backend 間の切替とは別の段階である。
- **ステータス表示と監査記録**：
  - CLIの終了時とTUIの `/status`（および macOS desktop の V2 snapshot）には、型付き判断器の設定値と直近 stage の観測値を分けて表示する。model・revision・quantization が得られない場合は「未確認」とする。管理対象 Clef の設定値は受入 profile のモデル・revision・量子化に結び付ける。実行時は worker の ready 応答で固定 hash・runtime・device・context を確認できた後だけ、そのモデル情報を観測値として記録する（容量拒否・起動失敗・ready 不一致では未確認のままとし、設定 profile ID で補わない）。
    - macOS desktop の V2 snapshot にも同じ型付き判断の診断を表示する。対象は起動中の service owner 全体で、会話別の使用量や再起動前の実績ではない。設定済み backend と観測結果、構築不可・未観測・容量拒否を区別し、snapshot 取得時の値として表示する。取得は判断器や接続確認を起動しない。旧 V1 snapshot には追加しない。
  - 使用量の件数は、結果が返った adapter 呼出の観測数であり、内部のHTTP再試行数や実推論回数ではない。途中で future が破棄された stage は別に数え、実行先・消費・実計算の停止を確認済みとして扱わない。
  - 監査の `typed_decision` には、要求IDを共通にした `start`・`attempt`・`settled` を保存する（入力本文や回答本文は含めない）。adapter を呼ぶ前に開始記録を書き、書けなければ呼び出さない。開始だけが残った場合、完了と消費は不明である。回答後の監査書込に失敗した場合は失敗件数を表示し、判断を再実行しない。
  - MCP・skill 選択の既存の生成仲裁は、typed 判断の audit とは別の `generative_arbitration` stage へ開始・応答・経過時間・使用量/欠測を記録する（設定された Provider の要求 model 名は記録するが、実 backend/model の確認として扱わない。本文・回答・エラー本文は保存しない）。
    - 応答受信は選択結果の採用ではなく、従来の回答検証を続ける。取消などで開始だけが残った記録は完了・消費不明。監査開始を書けなければ dispatch せず、完了を書けなければ回答を採用せず、再送しない。既知の消費量は保持する。仲裁の observer には監査完了後の最終 text だけを通知する。

### 固定artifactの管理・導入・修復コマンド

- **一覧と検証**：
  - `polaris decision list`：登録済み profile ID と容量の推薦をJSONで表示する（現在の登録は0件）。登録は導入や実行可否の確認ではなく、この操作で Jev/SemIf の設定は変わらない。
  - `polaris decision verify PROFILE_ID`：導入済みの固定 generation を再利用する前に、worker/model の全 size・SHA を読み取り専用で照合できる。成功時は profile・generation・モデル revision・量子化・照合した hash とバイト数をJSONで表示する。未受入・未導入・破損・非対応の場合は理由を表示して失敗し、`Ctrl-C` で取消できる。copy・削除・backend 選択・有効化・推論は行わない。
    - 結果は読み取り時点の確認であり、その後の置換、実行時の容量、モデルの応答品質を保証しない。既存 generation がある場合に再 import で上書きする必要はなく、固定 profile を選んだ通常起動でも実使用前の照合を行う。
- **手元の固定 artifact からの導入（`plan` / `import`）**：
  受入済み profile と配布情報が登録された後は、手元の固定 artifact を次の管理コマンドで導入できる（`PROFILE_ID` と2つの絶対 path を対象に置き換える）。
  ```sh
  polaris decision plan PROFILE_ID --worker /absolute/path/worker --model /absolute/path/model.gguf
  polaris decision import PROFILE_ID --worker /absolute/path/worker --model /absolute/path/model.gguf
  ```
  - `plan` は取得元、license/NOTICE、component 一覧、size/SHA、導入先、必要な copy 領域を表示するだけで、ファイルを取得・配置しない。
  - `import` は新しい計画を表示して `y/n` を求める（非対話実行では `--yes` が必要）。network を使わず、指定ファイルの全 size/SHA を照合して新しい generation へ copy する。取消・破損・競合時は既存 generation を残す。成功しても backend の選択・有効化や推論は開始しない。
  - 以前の計画や確認記録を再利用せず、導入直前にも固定 lock と導入先を照合する。配布情報が不足する profile は導入できない。
  - 現在の空 lock で `plan`・`import` を実行しても、受入未完了の案内で終了する。
- **既存 generation の修復（`repair`）**：
  既存 generation を修復する場合は、owner を終了し、同じ固定 artifact を手元に用意して次を実行する。
  ```sh
  polaris decision plan PROFILE_ID --repair --worker /absolute/path/worker --model /absolute/path/model.gguf
  polaris decision repair PROFILE_ID --worker /absolute/path/worker --model /absolute/path/model.gguf
  ```
  - 新しい copy の全SHAを照合した後に atomic に交換し、旧 generation を計画に表示する `.recovery-…` へ丸ごと残す（旧内容や追加ファイルを削除せず、設定・有効化は変更しない）。切替後の中断や保存結果不明では、新旧両方を保持するため、再実行前に `decision verify` と表示された保持先を確認する。GUIにも「既存 generation を保持して修復する」を用意している。
  - 修復は別の確認を求め、非対話実行では `--yes` が必要である。既存 directory の置換・管理操作の競合・切替前の取消や copy 失敗では切り替えない。保持先を自動で有効化したり、以前の確認を再利用したりはしない。受入未完了、非対応、alias や保護条件を満たさない既存 directory は修復しない。
  - GUI の修復計画は、保持先を含めて同じ CLI child へ確認する。導入計画の確認を修復へ流用できず、対象・操作を変更したら計画を作り直す。保持先表示は計画値であり、処理を中断した場合に配置済みという証明にはならない。

### 固定配布元からの取得（`plan-download` / `download`）

固定 download 情報まで登録された profile では、手元に worker/model を用意する代わりに、次の管理コマンドで取得できる（現在は受入済み profile が0件のため、この経路もまだ利用できない）。

```sh
polaris decision list
polaris decision plan-download PROFILE_ID
polaris decision download PROFILE_ID
polaris decision verify PROFILE_ID
```

- `plan-download` は取得URL・転送許可先・size/SHA・用途・license/NOTICE・導入先・取得容量・必要ディスク空き・全体期限を表示するだけで、通信しない。
- `download` は新しい計画を表示して確認を求める（非対話実行は `--yes` が必要で、以前の計画への承認は再利用しない）。表示した配布先以外へ自由に接続せず、認証情報を付けずに HTTPS で取得する。通常起動・初回判断・agent 実行中の自動取得は行わない。
- 必要ディスク空きには、取得用の一時領域、導入用 copy、予備を含む。
- 両ファイルのサイズとSHAを照合してから導入し、成功しても backend を選択・有効化しない。取得・検証・導入全体の期限は2時間で、期限後は取消を伝えて処理の終了を待つ。`Ctrl-C` でも停止を要求できる。結果が確定しなかった場合は、再取得を繰り返す前に `decision verify` で状態を確認する。
- 既存 generation がある場合、通常の `download` は取得前に拒否する。取得した固定 artifact で修復する場合は owner を終了してから、`plan-download` と `download` へそれぞれ `--repair` を付ける。旧 generation は、手元の artifact による修復と同じく計画に示した `.recovery-*` 先へ保持する。
- macOS インストーラの「モデル」ページにも「Clef判断器の導入と選択（任意）」がある（現在の登録は0件であり、導入・検証ボタンは表示しない）。
  - 「登録 profile を確認」で同梱 CLI の登録と容量推薦を読み、登録がある場合だけ profile を選べる。手元の worker/model を使う場合は2ファイルを選び、取得する場合は「固定配布元からダウンロードする」を選ぶ。表示された取得元、容量、用途、license/NOTICE、size/SHA、導入先を確認して、今回の計画へ承認を返す。
  - 確認待ちは120秒で、対象・取得方式を変えた場合や期限切れ時は計画を作り直す。通常 PATH のコマンドや project 指定の実行物は起動しない。
  - 登録 profile を選んだ後は、元ファイルを選ばずに「導入済み generation を検証」を実行できる。固定 hash の照合結果、未導入、受入未完了、整合性不明、非対応、取消を表示する。profile の変更や取消で以前の検証結果を消す。
  - GUI の build と合成試験は、実GUIでの操作や実モデル受入の証明ではない。

## ChatGPT認証

```sh
polaris login
POLARIS_PROVIDER=codex polaris -p "Cargo.toml は何行か"
```

- **ログイン画面の起動**：認証がない状態で `polaris` を対話端末から起動すると、ChatGPT または API key を選ぶログイン専用画面が開く（全登録が解除済みの場合も同じ）。登録済みアカウントの認証待機中は `Esc`・`Ctrl-C` で取り消せる。再認証が必要な登録は、表示された `polaris account reauth <登録ID>` で再認証する。非対話実行や明示 `--account` の不正指定ではログイン画面を開かない。

- **認証URLの操作**：Subscription の認証待ち画面には、クエリを含む認証URLを表示する。URLへの `Ctrl-click`・`Enter`・`o` で既定ブラウザへ開き、`c` でURL全文をコピーする。長いURLは `↑`/`↓` でスクロールできる。URLはこの画面だけに表示し、会話や監査ログには保存しない（CLIのログインでは端末へURLを表示する）。
- **期限切れ更新のテスト**：期限切れの更新経路を手で確認する場合は、テスト用の資格情報に限り `expires_at` を過去のUnix秒または `null` へ変更し、再実行後に `expires_at`、`account_id`、`0600` が維持されることを確認する（JSONを壊さないこと）。

- **プロジェクトと設定の隔離**：SwiftUIの作業画面は、選択したプロジェクトと会話を専用の保存先へ結び付ける。設定ファイルはプロジェクトの外に置き、登録時のディレクトリ identity と再接続時の identity が異なる場合は、保存済みの会話を維持したまま接続を拒否する。同じ設定を別のアプリから開くことも拒否する。終了時は下書きと復旧状態の保存を完了してから終了する。
- **添付ファイルと音声入力**：会話、task、child、ファイル、Gitの各欄は保存済みの状態と保護された読取結果から表示する。ファイル本文と添付は、明示的に選択した UTF-8 テキストだけを取り込む。添付は内容を確認してから保存または送信でき、**4件、各 64 KiB、合計 128 KiB** までに制限する（画像とバイナリは扱わない）。音声入力は macOS の許可を得た場合に下書きへ追加するが、録音の停止だけで送信はしない。
- **ローカルモデルの連携**：導入済みの Ollama または LM Studio は、アプリから明示的に更新したときに一覧へ反映する（到達できない endpoint は未導入とは判定しない）。主会話と役割別のローカルモデルは保存後に接続を確認してから実行へ使う。ツール必須の役割にはツール対応を確認できないモデルを割り当てず、未設定の役割をクラウドモデルへ自動的に切り替えない。役割保存の結果が不明な場合は同じ保存を再送せず、保存済み状態を照合する。
- **変更の反映（保留中の変更）**：モデルの編集は隔離した作業領域に保存する。元のプロジェクトへの反映は、完了後に「保留中の変更」を全件確認して許可する。実行の完了と反映の成功は別に表示し、期限切れや外部編集との競合では元ファイルを上書きしない。操作の詳細は[元ファイルへの変更反映](../apps/macos/README.md#元ファイルへの変更反映)を参照。

## TUIと会話

`--prompt` を省略すると対話TUIを起動する。資格情報がなく、`POLARIS_PROVIDER` が未設定または `openai` なら、ChatGPTサインインまたはOpenAI APIキー入力を選ぶ画面を出す（入力したAPIキーは `~/.polaris/api_key.json` へ `0600` で保存する）。`codex` を明示した対話起動でも、未登録または全登録解除済みなら同じ選択画面を出す。one-shot 実行では表示しない。待機中は `Ctrl-C` を2回押して終了する。

### 会話の保存・巻き戻し・下書き
- **保存先（legacy / v2）**：通常の `legacy` 起動は空の会話から始まり、送信済み会話を `~/.polaris/sessions/<会話id>.jsonl` と `<会話id>.meta.json` へ保存する（起動だけで終了した空会話は保存しない）。`workflow` または `strict10` を有効にした会話は `~/.polaris/sessions-v2/<UUID>/` を使う。v2 は raw イベント、世代付き snapshot、状態 marker を保存するため、ツール呼び出しと中間結果も回復対象になる。
- **巻き戻し（Rewind）**：保存済み v2 会話では、待機中に入力欄を空にして `Esc` を2回押すと巻き戻し候補を選べる。対象を選んで変更予定のファイルを確認し、`r` で確定すると、そのユーザー入力の直前の作業ファイルと会話文脈を新しい会話に復元する。元の会話は残るが、作業ファイルと一致しない会話への送信は拒否される。対象外の変更、外部編集との衝突、保存が不完全な境界、捕捉が2秒の上限を超えたターンは巻き戻し対象外となる。
- **下書きの自動保存**：保存済みの v2 会話では、入力欄の未送信の下書きを、入力が約0.35秒止まるたびに会話へ保存し、起動時と会話の切替時に入力欄へ戻す。`/` で始まる行と `/mcp secret` の行は下書きにしない。端末を閉じるなど終了処理を通らない場合も、直前の保存までは残る。詳細は[コマンド一覧](command-reference.md)にある。

### 画面表示とキー操作
- **ヘッダーとツール表示**：ヘッダーにはモデル、プロバイダ、作業ディレクトリ、累積使用量を表示する（失敗ターンの使用量は累計へ反映されず、プロバイダが usage を返さないときは `0` と表示する）。ツール呼び出しは `⚙ ツール名(引数)`、結果は `→ 要約` として表示し、長い表示だけを約200文字で打ち切る。Markdown の太字、インラインコード、コードブロックを整形する。
- **中断（`Esc` 2回）**：実行中は経過時間と中断キーを表示する。`Esc` 1回目は `Press Esc again to interrupt` と表示するだけで入力欄の下書きにも触れない。約2秒以内にもう一度押すと待機を中断し、それより遅いと1回目は数えない（すでに起動したOSサブプロセスは強制終了しない）。
- **入力欄**：入力欄には背景色を付けず、入力行の上下に幅いっぱいの灰色の罫線を引く。会話履歴に残る自分の発言は、従来どおり灰色の背景で表示する。
- **ステータス行と subagent 表示**：入力欄の下の行は、左側にモデル・推論強度・作業ディレクトリを、右端に workflow の段階（例：`workflow: implement`）を表示する。その下の行には、現在または直近の run で起動した subagent の数を `subagents 2/4 done · 1 running · 1 failed` の形で表示する（run の終了時にまだ完了を報告していない子は `failed` に数える）。
  - workflow が無効な会話では段階を表示せず、端末の幅が足りないときは、モデルや作業ディレクトリより先に段階を省く。
  - 件数が0の `running` と `failed` は省き、subagent の無い run では行ごと表示しない。
- **スクロール**：会話の履歴は、`PageUp`・`PageDown`（ターン実行中も可）とマウスホイールでスクロールできる。

### 会話の再開とプロバイダ・モデルの引き継ぎ
- **記録の保存**：別の会話を開くとき（`--resume` での起動、`/resume`）は、その会話を行った provider とモデルが最初から選ばれる。TUIは会話の保存ファイルに、provider、モデル、推論強度（および `openai` の場合は接続先URLのホスト部）を自分で書く。
  - `openai` の会話には、接続先（既定の OpenAI のホストか、`POLARIS_BASE_URL` で指した URL か）も書く。URL のユーザー情報・クエリ・フラグメントは書かない。
  - 書くのは、`/model` でモデルを選び終えたときと、入力を送る前に記録が無いか今の選択と違うときで、確認画面は出さない。入力が自動で新しい会話（sidechat）へ回るときは、その会話を作る時点で今の選択を入れるので、最初の要求の前から記録がある。
  - この記録は、`/memory configure` などで保存する設定とは別の項目である。`--remember` や `--tool-memory` などの起動オプションは入らない。
- **開くときの選択規則**：
  - 記録を優先して選ぶ。記録が無く設定を保存した会話は、その設定の provider とモデルを選ぶ。記録も設定も無い会話は、現在の選択で動く（この記録を書く前に始めて設定も保存していない会話、まだ一度も送らず `/model` も使っていない会話、保存先を持たない legacy 会話がこれに当たる）。設定だけを保存した会話には接続先の記録が無いので、provider とモデルだけで比べる。推論強度は記録するが、開くときには選び直さず、その起動で指定した強度に従う。
  - 保存したローカルモデル（Ollama または LM Studio）は、loopback のサーバーから在庫を取得し、保存したモデルがあってツール対応を確認できたときだけ採用する。
  - 保存したホスト型のモデルは、起動した provider（`codex` または `openai`）と接続先が同じときに選ぶ。`openai` は接続先も同じでなければならない。ローカルの OpenAI 互換サーバーで行った会話を既定の OpenAI の接続先で開いたときと、その逆のときは、provider とモデルが同じでも提供できないものとして扱う。
  - `/new fork` と巻き戻しは、今開いている会話の子を作る操作なので選び直さず、今使っている provider を引き継ぐ。`/model` で選んだローカルモデルは、子でも続く。
- **提供できない場合の送信ブロック**：会話を行った provider をこのプロセスが提供できないとき（ローカルサーバー停止、モデル不在、ツール非対応、起動 provider や接続先の不一致、`llamacpp` で保存した会話を別の provider の起動で開く、など）も、会話は開いて履歴を表示するが、**何も送らない**。送ろうとした入力は入力欄へ戻り、ステータス行が必要な provider・モデルと入手方法を1行で示す。これにより、ローカルモデルで行った会話が、人が選ばないままホスト型へ送られることはない（`/model` でモデルを選べば、その選択で送れる）。
  - 入手方法には、サーバーの起動、`POLARIS_PROVIDER=...` や `POLARIS_BASE_URL=...` での再起動などがある。
  - 記録も設定も無い会話は、比べる対象が無く、この確認の対象外である。この会話から `/new fork` や巻き戻しで作った会話も、同じく何も送れない。
  - 記録を保存できないとき（別の操作が project を使用中、未解決の管理操作がある、など）は、送る前にその旨を示して何も送らず、入力を戻す。`/model` の直後に保存できなかったときは、モデルを選んだまま、次に送る前に保存し直す。

### スラッシュコマンド

`/` で候補を絞り込み、`↑`/`↓` と `Enter` で実行する。コマンドは次の15個で、`/help`・候補・補完に同じ順で出る。状態照会や設定変更はローカルで処理する。履歴の圧縮は自動で行い、手動で起動するコマンドはない。TUIの `/web-search`・`/models`・`/browse`・`/attachment`・`/recipe`・`/handoff`・`/remember`・`/account`・`/usage` は提供しない（削除した名前は `/doctor`・`/skills`・`/clear`・`/review` なども含め、何も実行せず、代わりの操作を1行で答える）。`/usage` は `/status` のトークン表示と重なるため設けない。CLI の `polaris account` は保持している。全コマンドの構文・出力と、削除した名前の一覧は[コマンド一覧](command-reference.md)にまとめる。

| コマンド | 内容 |
| --- | --- |
| `/model`、`/permissions` | モデル（ホスト型または接続済み Ollama / LM Studio の `Local model`）、起動時の境界内で承認ポリシーを選び直す。推論強度の固定は起動時の `--effort` で指定する。`Local model` を選ぶと、接続済みの Ollama と LM Studio からモデルを取得し、次の一覧で選択できる。ツール対応を確認できたモデルだけを採用し、次のターンから反映する。推論強度はこのピッカーでは選ばない。`/permissions` は起動時の承認境界を超える選択を拒否し、固定の sandbox と再起動用の引数を表示する。 |
| `/new`、`/new fork`、`/resume` | 会話を新規作成、複製（分岐）、再開する。`/resume` は作業ディレクトリ別にグループ化し、現在のディレクトリを先頭に表示する。一覧の各行には相対時刻、メッセージ数、最初のユーザーメッセージの60文字プレビューを表示し、30日を超えた会話は絶対日時で表示する。legacy では壊れた行より前までを読み、v2 の破損・世代不一致は原文を切り捨てず拒否する。選んだ会話への送信は既存ファイルへ追記する。 |
| `/status`、`/diff`、`/help` | 現在の状態（project root・ログイン状態・対話ID・使用トークンを含む）、未コミットの変更、コマンドとキーの一覧を表示する。 |
| `/mcp` | 登録・外部接続上限（起動時の `--mcp-external` が上限）と認証情報の参照名を表示する。`setup` で検出・登録、`check <server>` でカタログ取得、`enable <server>`・`disable <server>` でプロジェクトの有効化を変更する。 |
| `/mcp materialize <名前>` | 検出したパッケージを確認後に取得・固定する。登録は別途確認する。取得処理の終了までは待つ必要がある。 |
| `/mcp secret set`、<br>`/mcp secret delete <参照名>` | 専用画面で秘密値を入力し、または保存済みの認証情報を確認後に削除する。`set` の引数へ値を書かない。値も文字数も表示せず、`Esc`・`Ctrl-C` で入力を取り消せる。 |
| `/login`、`/login list`、`/login decider` | アカウントの登録、登録済みアカウントの一覧、判定器の選択を行う。判定器の選択は次の起動から有効になる。 |
| `/logout [登録ID]` | 追加確認なしで指定認証を解除し、結果を表示する。省略時は使用中の認証が対象。 |
| `/memory search <query>`、<br>`/memory get <session> <id>`、<br>`/memory source <session> <id>`、<br>`/memory import <JSONL>`、<br>`/memory forget <session>` | 記録の取り込み、検索・参照、確認後の記憶削除を行う。取り込みと削除は巻き戻しでは取り消せない。 |
| `/memory configure on\|off` | 圧縮前履歴の記憶設定を、開いている会話に保存する。 |
| `/sync`、`/sync status` | 共有の状態を、この端末に残した記録から表示する。先頭の行が示すとおり remote には接続せず、remote の現在の状態ではない。 |
| `/export` | 会話をMarkdownへ書き出す。ファイル名省略時はタイムスタンプ付きの名前を使う。 |
| `/init` | カレントディレクトリに `AGENTS.md` の雛形を作成する。既存時は何もしない。 |
| `/quit`、`/exit`、`/q` | polaris を終了する。 |

- MCP の外部接続は起動時の `--mcp-external` が上限となる。カタログ取得・登録・パッケージ取得は、上限や承認設定が拒否した場合には実行しない。秘密値は通常入力・履歴・モデルへ送らず、専用入力画面でのみ扱う。

### 登録済みUnity MCPの固定配置

CLIの `mcp configure` は、有効な既存 stdio 登録1件を対象に、ローカルの Unity MCP を専用の version directory へコピーする。対応する preset は `unity-local-v2` だけで、登録の唯一の entry 引数が指定元の `build/index.js` と一致する必要がある。

```sh
polaris mcp configure <server-id> --preset unity-local-v2 --source /absolute/path/to/unity-mcp-ts
```

- 表示されたコピー元・配置先・ハッシュ・登録差分を確認して承認する（非対話実行では `--yes`）。承認前に配置先や管理操作の記録は作らない。
- コピー対象は `build/`、`node_modules/`、`package.json` と存在する lockfile である。`node_modules/.bin` と、依存 package 配下の固定リストにある同名 directory を除外し、実在する除外先を確認画面と manifest へ列挙する。検証済みの特定の esbuild hardlink pair だけを独立した通常 file へ展開する。別の構成や検証できない file は拒否するため、その場合は元の登録を確認する。
- 配置の完了後に登録を更新し、次の実行から新しい cwd・entry、`auto_2024_compat`、loopback 限定の通信設定を使う。構成中に download、プログラムの起動、接続確認は行わない。旧 runtime と未参照のコピーは保持する。途中で結果不明となった操作は繰り返さず、管理操作の記録と保存済み状態を確認する。
- 構成後は `polaris mcp check <server-id>` でカタログを確認できる（Unity Editor への実接続は示さない）。`polaris mcp disable <server-id>` は現在の project での利用を止める操作で、旧登録の復元ではない。

### AGENTS.mdの扱い

指示ファイルは2種類を区別する。読取は各ファイル 256KiB 以内。

- **グローバルの `~/.polaris/AGENTS.md`（本人の規則）**：
  - `Always on` 節を、親エージェントの各モデル要求の直前に読み直し、system の `## Project rules` に入れる。変更はその要求から反映する。
  - グローバルのファイルが読取不能、不正UTF-8、上限超過、読取中の変更、symlink や保護対象ファイルへの差し替えのときは、要求を停止する（旧規則や空の規則へ黙って切り替えない）。
- **プロジェクト直下の `AGENTS.md`（信頼しない外部テキスト）**：
  - `Always on` 節を起動時に1回だけ読み、同じ100トークン以内に切り詰め、制御・不可視文字と各種の改行を除いたうえで、全行の先頭に `| ` を付け、セッションごとの乱数を含む枠（`⟦REF-…⟧`）で囲んで、**system ではなく独立したメッセージ**として送る。枠の記号を含む本文は全体を載せない。
  - 権限・tool・段階・sandbox・承認には影響しない。起動後に書き換えてもその実行の文脈は変わらない（resume で別のプロセスから開いたときは読み直す）。読めないファイルはその実行では載せず、警告を一度だけ表示する。
- **圧縮版（既定で有効）**：
  - 各 `Always on` 節を、モデルが短い記法に書き換えた写しである。節が変わったときだけ、起動時に1回、`giant` の重み（既定で sol）で作る。
  - 作った写しは、全体なら `~/.polaris/agentsmd-wrap.md`、プロジェクトなら `~/.polaris/state/wraps/<パスのハッシュ>/agentsmd-wrap.md` に置く（リポジトリには書かない）。要求のたびに行うのは、元の節の SHA-256 を写しの先頭の記録と比べることだけで、トークンを使わない。
  - 写しは「全規則が覆われ、100トークン以内で元より小さく、元に無いURL・パス・命令を含まない」ときだけ使い、それ以外（古い、壊れた、作れなかった）は元の節をそのまま使う。作れなかった節は、変わるまで再試行しない。プロジェクトの写しも従来どおり引用として送る。止めるには `~/.polaris/config.toml` の `[prompt]` に `agents_wrap = false` と書く。
- ※ どちらも、本文が変わらない確認や対象節以外の編集で、固定プロンプトに時刻・更新番号を追加することはない。子エージェントへの新規注入、別ディレクトリの探索、実行権限の変更は行わない。

### 内部プロファイル（`unattended`）

`--prompt-profile unattended`、または本人の `~/.polaris/config.toml` の `[prompt] profile = "unattended"` で、無人実行向けの4行（質問しない、直接変更して検査を示す、分析で止まらない、読取りの委譲は約20ファイルまたは100KBを超えるときだけ、他の委譲は大きく独立した部分だけ）をルートの system に加える（既定は `default` で何も加えない）。
- プロジェクトの `.polaris/config.toml` に `[prompt]` を書くと読込みエラーになる。
- プロファイルの文面は実行ファイルに組み込まれており、ファイルから読まない。規則の枠100トークンを、プロファイルが先に、残りをグローバルの規則が使う。

### files.mdの自動更新

`files-md-writer` 型を導入している場合、root のツール変更後に対象ディレクトリの `files.md` を自動更新する。**既定は無効である**（生成した `files.md` を要求へ載せる経路は無く、ディレクトリが増えるたびに subagent を起動する分だけが残るため、2026-09-19に既定を `false` へ変えた）。必要なプロジェクトでは、グローバルまたはプロジェクト設定で有効にする。

```toml
[files_md]
auto_regenerate = true
```

この設定は root 起点の自動更新だけを止める。`spawn` による明示的な subagent 実行は維持される。

`spawn` の型、設定、出力検証、深さの制限は[subagent](subagents.md)にある。

- TUIで、会話に保存した role の束縛が解決できなくなったとき（role が `agents/` に無い、束縛先の tier に provider が無い、など）は、TUIを終了しない。その会話の委任を止めたままターンを実行し、どの role も許可しない。役割名と理由を、履歴へ会話ごとに1回だけ示す。解決できる束縛は、これまでどおり効く。

## 隔離実測のbroker連携

外側の native sandbox からツールを実行する開発用連携では、launcher が `POLARIS_SANDBOX_BROKER` と `POLARIS_SANDBOX_BROKER_TOKEN` を組で設定する（未指定なら通常の実行経路を使う）。
- 接続先は同じ launcher が渡す `HOME` 以下の `.local/share/codex-benchmarks/<32桁の小文字16進ID>/broker.sock` に限定し、非絶対パス・親ディレクトリ参照・リンク経由の接続を拒否する。任意の接続先 root を許可する設定はない。
- `HOME`・socket・token は信頼する launcher の設定として扱う。実際の接続先、ファイル範囲、ツールの実行権限は外側の sandbox と broker が独立して制限する。公開パッケージに共通実測ランナー自体は同梱しない。
